# Seaside part1 分层素材接入方案

> 2026-10-30 交接更新：本文以下是原日期的历史方案。当前工程为 Project6.4，PNG 与布局统一在 Project6.4/Assets/Art；旧 Figures PNG 和 Project/ 已归档。当前分层场景没有旧整图 F6/F7 开关。当前入口见 [协作指南](../CONTRIBUTING.md) 和 [场景规范](SceneHierarchy.md)。


2026-10-28，根据 `Figures/part1/` 的20张PNG及 `part1.json.ps` 逐项检查。此文为新素材评估与后续实施方案，尚未导入Unity或修改场景。

## 新素材解决了什么

已有独立的背景、地形外观、桥柱、植物、光效和检查点状态图，能够分别排序、定位、缩放和绑定游戏状态。先前整张合成图中“动平台就连背景一起动”的限制得到缓解。

但可玩地形仍主要集中在 `bg0.png` 一张大图中，没有全部拆成独立平台/墙面模块。分层解决了背景与前景混在一起的问题，没有自动解决美术轮廓与原地图碰撞不一致的问题。

## 素材分工

|素材|实际观察|建议用途|
|---|---|---|
|bg3.png|大幅蓝紫色渐变与纹理，未画可玩平台|最底层远景，优先接入|
|bg1.png、bg2.png|远处建筑/岩体，透明区域及部分黑色遮挡形状|中远景，先固定位置，验证遮挡关系|
|bg0.png|大量主要墙体和地形仍合在一张图里，还含暗部及青色局部|作为地形美术参照；后续再按平台/墙体区域拆模块|
|bridge1/2、pillar1/2|独立桥柱或桥体，部分含侧面与阴影|独立美术对象；根据玩法决定顶部是否对应现有平台|
|thorn1～6|白色或浅青色植物形态|可作危险区域外观候选，但不能仅凭文件名认定整株都是死亡区|
|checkpoint_off/on|独立底座与带高亮区域的版本|绑定已有检查点状态，保留触发器与复活锚点|
|lighthouse|独立灯塔|装饰或终点视觉标识，按已有终点逻辑另行绑定|
|water、light、lightspot|水纹、光束与光点|独立效果层，先静态显示，后续再考虑动画|

bg1/bg2含有依赖其他层遮盖的形状；移动层间相对位置可能露出原本被遮挡的部分。因此初版先不用视差滚动，确认完整远景能覆盖镜头范围、没有露底后，再给纯远景增加轻微视差。前景地形、尖刺与检查点必须与碰撞位置同步，不能跟着远景视差漂移。

## 利用布局文件自动摆放

`part1.json.ps` 虽然扩展名是 `.ps`，实际内容是JSON布局数据，不是需要执行的PowerShell脚本。它包含20个图层引用及每个图层的x/y/width/height，引用图片全部存在。

- 逻辑画布：4288×2107。
- PNG实际尺寸约为布局尺寸的1.5倍，例如bg0实际6434×3161、布局4290×2107；各图有少量像素取整差异。
- 不能把文件坐标当作PNG原始像素，也不能直接沿用旧整图7783×4214的换算参数。
- 建议编写一次性Unity编辑器导入工具：按JSON的逻辑矩形定位，图片用实际Sprite尺寸校正显示宽高，随后将每层保存为可单独编辑的对象。

假设逻辑画布左下角世界位置为O、每个逻辑像素为s个世界单位，图层采用中心Pivot，可按以下公式初步还原：

```text
世界中心x = O.x + (x + width/2) × s
世界中心y = O.y + (2107 - y - height/2) × s
显示宽度 = width × s
显示高度 = height × s
```

此公式按布局坐标原点在左上角、y向下的方式解释；需通过还原图与实际美术对照确认。子图有少量超出逻辑画布的部分，不能强行裁掉或以其包围盒重新计算所有图层的比例。

以世界宽155为起点时，s=155/4288，画布世界高约76.163；这只是校准候选值，仍需用起步地面和远端墙边等参照点确定位置/比例。JSON层列表可作为初始叠放顺序线索，最终Sorting Order仍要根据可见遮挡关系核对。

## 推荐执行顺序

1. **新建分层预览场景。** 从当前已保存的Seaside场景复制，保留用户编辑。层对象统一放在独立美术父对象下，碰撞、角色与地图逻辑不移入该父对象。
2. **还原静态分层构图。** 使用JSON导入背景和装饰，先建立可单独开关的图层，核对透明区、黑色遮挡、光效和图片位置。阶段目标是正确显示，不是自动生成碰撞。
3. **保留原碰撞，只调整外观。** 优先替换独立桥柱、检查点及适用的危险区域外观，逐个查看角色脚底/侧面与可见边缘是否贴合。不要把一张植物图任意拉满整条尖刺带。
4. **拆分bg0并适配地形。** 按现有连续的平台和墙体区域准备独立外观。短部件直接定位；需要反复改变尺寸的长条，适合准备带端头/边缘的可平铺模块或九宫格素材。Unity的Sliced/Tiled模式需要正确设置Sprite边界，不能直接把整张bg0设为Tiled。参见[Unity SpriteDrawMode](https://docs.unity3d.com/ja/6000.0/ScriptReference/SpriteDrawMode.html)与[边界设置要求](https://docs.unity3d.com/ja/6000.0/ScriptReference/SpriteDrawMode.Sliced.html)。
5. **逐段验收后隐藏对应白盒。** 只有该段外观与真实碰撞已经贴合，才隐藏该段Ground的SpriteRenderer；BoxCollider和SeasideCell继续保留。核对短跳4/长跳8/冲刺8、贴墙探测、尖刺触发、检查点与复活。

这个顺序能先用上背景和装饰，同时保留现有角色手感和关卡进度。如果最终选择完全遵循美术图地形，则应在另一个关卡副本中重建碰撞与检查点，重新验证路线，不把它当作单纯换皮。

## 检查点的具体注意事项

checkpoint_on实际212×298，off实际212×66，不能都用中心Pivot直接互换，否则底座可能上下移动。建议以底座底部中点统一锚定，切换状态只切换视觉子对象；使用现有检查点编号、触发器、复活点，不根据PNG透明轮廓生成触发器。重开时还要恢复未激活外观。

## 为什么不自动按PNG轮廓生成整关碰撞

bg0包含纹理、阴影、侧面及装饰边缘，其透明/不透明边界不等于人物应该接触的玩法轮廓。按图片自动生成的多边形可能把暗部、缝隙或装饰纳入碰撞。现有碰撞已经参与角色手感与回归检查，应作为当前换皮基准。
