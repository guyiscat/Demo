# 五关流程与自动存档

2026-11-20起，运行根目录statgame.cmd，开始页提供“开始游戏”“继续游戏”“游戏选项”“退出游戏”四项。当前游戏顺序为海边→森林→矿洞→雪山→灯塔。森林/矿洞/雪山/灯塔各自的cmd仍可用于从该关入口测试，其成品也包含后续跳关所需场景和开始页。

## 自动跳关

各关原有通关条件保持：海边终点、森林终点、矿洞读完井底遗物、雪山选择带走残章并读完末句后，等待0.8秒自动进入下一关。切换前先存下一关入口，退出发生在过渡期间也能从下一关继续。雪山选择“留下”保留剧情结局，不进入灯塔；灯塔完成后显示最终结局，不再加载不存在的下一关。

等待秒数在Assets/Resources/GameSystems.asset的“通关后自动进入下一关等待秒数”（nextLevelDelay）调整。EditorBuildSettings按开始页、海边、森林、矿洞、雪山、灯塔排列；测试夹具不加入。各独立入口构建同样包含六个必要场景，只改变启动场景，不改变流程次序。

## 存档点与继续

触碰存档点立即更新最近安全复活点并写入本地存档。保存关卡、存档点编号、时间/死亡统计、矿洞工作台及电梯状态、森林两侧水车解锁状态；继续时使用场景中对应RespawnAnchor，不记录半空坐标，不恢复未完成的临时信标/冲刺或电梯瞬时位置。矿洞已启动电梯会恢复运行，灯塔追赶从当前安全点重新计时并恢复道路。

本轮只在既有无尖刺的中立静态平台增设标记，不增加地形、尖刺或捷径。矿洞原2个增加5个共7个；雪山原5个增加1个共6个；灯塔原4个增加1个共5个。其他候选位置缺少不与已有点重复的中立落脚面，保留既有安全点，不把存档放到灼热/冻伤表面或悬空处。

这些编号是唯一标识，不代表必须递增触发；依旧使用最后实际接触的点。R回最近点，Ctrl+R重开当前关卡并覆盖该关进度；暂停面板可“返回开始页”。退出后从“继续游戏”恢复最新进度。无有效存档时“继续游戏”置灰；开始新游戏遇到可继续进度会先弹出确认，原进度另留.previous副本。最终结局后不提供越过结局的继续入口。

存档为Application.persistentDataPath/campaign-save.json，Windows通常位于用户AppData/LocalLow/<公司名>/<产品名>/，以Unity当前PlayerSettings为准。写入使用.tmp后原子替换，上一份完整文件保留.bak；主文件损坏优先从.bak恢复，未知版本、无效关卡或异常编号不会作为加载路径。存档不写入项目Assets、不随工程ZIP上传。编辑器退出Play亦保留最近已激活点；直接进入某关Play或运行其独立入口会从该关入口开始并更新同一进度槽，需恢复已有进度时请使用开始页“继续游戏”。

## 菜单与字体

四项菜单使用原开始页的背景、徽标、标题等8层主题美术，只重排按钮区域。按钮标签为实际TextMesh文字，支持鼠标、上下/W/S和Enter/空格；功能按StartMenuAction枚举绑定，不再依赖旧三项下标。四项按钮、所有HUD、设置/帮助/暂停/对话和地图文字共用GameSystems.systemFont指向的阿里巴巴普惠体。原主题图片里的文字仍是图片的一部分。

字体运行资源Assets/Resources/Fonts/AlibabaPuHuiTi-Regular.otf与根Assets/AlibabaPuHuiTi-3-55-Regular.otf字节一致。字体全局入口GameTypography/GameUIStyles已经覆盖当前五关，后续复用公共界面也会沿用。

## 维护与验证

CampaignFlow、CampaignSave、CampaignCheckpointPersistence为公共系统脚本。CampaignSetup.Install仅在隔离批处理工程对当前保存场景增量增加存档点和菜单，不重建整张地图；按标识避免重复添加。测试时使用独立-campaignSavePath，旧各关物理检查不写玩家进度。

Tools/BuildAndTest.ps1 -StartupPage额外检查全流程自动跳关、各存档点、菜单继续/新游戏确认、损坏恢复、森林水车和矿洞状态恢复，并用两个独立游戏进程验证关闭后读取存档。各关单独构建仍跑其原机制回归。实际报告、界面检查、失败与修复见Docs/Logs/Work/20261120-campaign-saves/work-log.md；自动触发终点和局部物理检查不代表人工完整路线难度验收。
