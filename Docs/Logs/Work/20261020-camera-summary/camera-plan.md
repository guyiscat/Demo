# 当前 v3 镜头跟随优化方案

日期：2026-10-20。本次核对并总结已有实现，不改镜头参数、不改玩法、不重新打包。依据 CameraMotion.cs、SeasideCamera.cs、保存场景参数和现存回归报告；本次没有重新执行测试。

## 目标与结构

目标：普通移动稳、转向不猛甩、跳跃不频繁抖动、冲刺和下落跟得上、复活不拖镜头。
使用自定义 CameraMotion，不依赖 Cinemachine。SeasideCamera 负责连接角色状态和实际相机；CameraMotion 负责可独立测试的位置/缩放算法；CameraTuning 保存 Inspector 可调参数。

角色物理位置更新 → Rigidbody2D 插值后的 Transform → LateUpdate 读取位置与速度 → 死区锚点 → 朝向预留视野/速度预测/垂直偏置 → 按状态阻尼 → 安全取景和地图边界。
LateUpdate 在本帧普通 Update 之后、渲染之前执行，不是等画面渲染完再跟随。保存场景中人物 Rigidbody2D 的 m_Interpolate=1，已启用插值。

## 1. 用死区过滤微动

锚点只在角色超出窗口时移动，不把人物每次小幅偏移直接传给画面：

|参数|当前值|用途|
|---|---|---|
|horizontalDeadZone|左右各 0.8 格|过滤左右微动|
|verticalDeadZone|上下各 1.5 格|缓和跳跃顶点、落地附近小变化|
|wallVerticalDeadZone|上下各 0.7 格|贴墙悬停/慢滑时更及时跟上高度|

这些是世界格数，不是屏幕像素。人物边长 2 格，横向半死区相当于 0.4 身位。死区过滤的是跟随锚点，速度预测/前视偏移仍可能让最终镜头小幅调整，不是整个死区内绝对锁死相机。

## 2. 横纵分开平滑，按动作响应

采用带速度状态的 SmoothDamp，而非每帧固定比例 Lerp：

|状态|横向 smoothTime|纵向 smoothTime|
|---|---|---|
|普通跑动/跳跃/落地|0.18 秒|0.24 秒|
|冲刺|0.10 秒|目标切向 0.10 秒|
|快速下落，vy < -12 格/秒|0.18 秒|目标切向 0.13 秒|

数值越小响应越快，但它是阻尼参数，不代表严格在该秒数内到位。纵向响应参数自身还用 0.10 秒时间常数平滑切换，避免一跨速度阈值镜头响应就骤变。冲刺横向使用状态对应参数，没有另外做参数渐变。
贴墙没有独立的强锁镜头或纵向专用 smoothTime；使用较小死区、普通纵向阻尼，并取消下落前视目标。

## 3. 向运动方向预留视野

实际横向速度大于 0.35 格/秒才选择前视方向。前视目标为运动方向 × 2.2 格，以 0.22 秒阻尼变化。转向时前视从旧方向逐渐转到新方向；停下时逐渐回到 0。
另加 vx × 0.10 秒的速度预测，限制在 ±1.5 格。正常跑速 10 格/秒时增加约 1 格预测；冲刺 25 格/秒时达到 1.5 格上限，避免高速把镜头推得过远。
前视和预测只改变相机目标，不改变角色速度、跳跃高度或冲刺距离。

## 4. 上方视野和下落前视

默认垂直偏置 verticalBias=1.1 格，给角色上方更多观察空间。没有贴墙且没有落地时，根据 -vy/22 的比例引入最多 1.3 格下落偏移，以 0.22 秒阻尼变化。
注意：1.3 格是对上方偏置的扣减，不是额外固定把镜头压到人物下方 1.3 格；达到最大值时，目标偏置为 1.1-1.3=-0.2 格，尚需叠加死区锚点和跟随滞后。
落地或贴墙时，下落前视目标回到 0，并平滑收回。高速下降还会触发更快的纵向追随，两者配合减轻落点来不及看清的问题。
当前没有落点射线预测、识别下个平台、起跳全程锁定高度或落地专用冻结逻辑，不能把这些当作已实现功能。

## 5. 视野、地图边界和安全取景

普通正交相机 orthographicSize=9，即可见高度约 18 格；16:9 下宽度约 32 格。普通跑跳不会自动改变这个尺寸。
地图尺寸 155×73 格。横向用当前尺寸与屏幕比例计算可用镜头中心范围，视口比地图更宽时居中。纵向采取带上下余量的中心限制，允许少量边缘留白，不是严格完全不露地图外区域。
平滑跟随之后还有安全取景限制：中心与人物的横向距离不超过可见半宽的 72%，纵向距离不超过可见半高的 67%，随后再应用地图边界。它是接近画面边缘时的保护，不在正常微动时持续把人强拉到中心；地图边界极端情况下仍有优先影响。
普通模式没有动态冲刺拉远、相机震动和屏幕像素取整。地图网格是逻辑单位，并不意味着相机应按格移动。

## 6. 全图、复活与暂停

Tab 全图模式：目标位置为地图中心，移动与缩放阻尼参数均为 0.32 秒。全图目标尺寸取 max(地图高×0.62, 地图宽/屏幕比例×0.55)，为地图保留余量。
模式切换时保留当前镜头位置，清除旧追随速度和缩放速度，重置锚点，并跳过切换当帧的一次推进，让过渡从下一时间间隔开始。前视内部变量没有在这里全部清零；完整重置发生在 Snap/Reset。
复活：Respawn 调用 camera.Snap，立即定位复活处并清零速度、前视及缩放状态，避免镜头跨地图追赶复活点。暂停：Time.timeScale<=0 时停止 LateUpdate 中的跟随推进。

## 7. 时间一致性与实际验证范围

平滑显式传入 deltaTime，纵向参数切换使用指数时间系数；单次 dt 限制在 0.0001～0.1 秒。它减少帧率依赖，但不代表卡顿时或不同帧率逐帧完全一致。
最新现存 playtest-regression.txt 中：

- 同一脚本路径以 30/60/120 FPS 执行，并按相同时间点采样。相对 120 FPS，30 FPS 最大位置差 0.436 格，60 FPS 最大位置差 0.144 格。
- 小幅站立抖动没有推动跟随位置，偏差小于 0.01 格。
- 全图切换平滑收敛，测试中最大单步位移 0.603 格（120 FPS 指定测试场景）。
- 复活重置测试通过，没有遗留速度和旧前视。

这是四项镜头逻辑回归，不是说全部 165 项都是镜头测试。路径涵盖跑动、转向、跳跃、高速段、墙边缓慢下降及全图切换；该路径下降速度为 7 格/秒，未覆盖 vy<-12 的快速下落响应阈值。当前资料也不足以保证所有宽高比、地图角落和真实长跳冲刺组合都已验收。
证据：Docs/playtest-regression.txt、Docs/camera-framerate-traces.csv、Logs/Build/20261020-192517-945/。本次只核对既有结果，没有重新跑测试或重新生成试玩包。

## 8. 后续微调顺序（建议，尚未应用）

在 Unity Hierarchy 选 Main Camera → SeasideCamera → Tuning。保存场景后，重新构建才会更新 Windows 试玩包；只改字段默认值不一定改变场景已序列化参数。

1. 普通跟随仍拖：Horizontal Smooth 0.18→0.14，Vertical Smooth 0.24→0.20。先调这一组。
2. 两墙反复蹬跳时横向晃：Look Ahead Distance 2.2→1.5～1.8，Look Ahead Smooth 0.22→0.26～0.30。预判减弱，稳定性上升，但前方视野会少一些。
3. 跳跃上下摆动太多：Vertical Dead Zone 1.5→1.8～2.0；代价是相机开始追赶高度更晚。
4. 慢滑跟得不够近：Wall Vertical Dead Zone 0.7→0.4～0.5；代价是慢滑时画面更容易随人物移动。
5. 下落落点仍不清楚：先补快速下落阈值两侧、冲刺转下落及贴墙切换测试，再考虑 fastVerticalSmooth、fallLookAhead，而不是只堆更强的预测量。

推荐真人验收顺序：原地微动、起停、连续反向、短/长跳、双墙蹬跳与悬停/慢滑切换、水平/斜冲碰墙、长距离下降、边角、Tab 来回切换、死亡复活。每次只改一组，保存对照录像和参数记录。后续应补充 4:3/16:9/超宽屏及 30/60/120 FPS 组合测试。
