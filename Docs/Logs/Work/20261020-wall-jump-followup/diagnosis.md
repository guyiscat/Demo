# 2026-10-20：用户反馈墙跳仍然无变化，询问是否因为不能空中跳

本次仅诊断，不修改移动规则或重新出包。

检查来源：Runtime/20261020-193243-861-327b6f.log 及对应 engine.log、SeasideMotor.cs、Movement.asset。
实际试玩会话 build=v3-wall-jump-20261020，engine.log 的 Mono 路径指向当前 v3/Play，说明这次试玩确实加载了新版，而非旧版包。

当前规则：地面跳；贴墙墙跳；离开最后有效墙面后 0.10 秒内墙跳。没有自由二段跳。地面土狼 0.14 秒，墙跳推离锁定 0.12 秒。空格必须是新的按下边沿。
日志证据：19:33:10.850 记录墙面已不在当前探测中（wall=0），仍借 wallGrace 执行 WALL_JUMP，说明离墙容错实际生效。
19:34:03.030 记录 JUMP_REQUEST，位置 (40.74,17.79)，wall=0、groundGrace=0、wallGrace=0、lock=0，随后没有起跳执行事件。同类事件还有 19:33:08.033、19:33:59.813、19:34:09.863。
因此可以确认部分按键发生在无地面/墙面资格的空中状态，按当前规则会被拒绝；不应概括为“空中一律不能跳”，因为贴墙和短暂离墙本身也是空中墙跳。
日志没有逐帧墙面接触状态，也没有为每个失败事件保存按键全过程；不能证明用户感知的所有失败都只由 0.10 秒窗口耗尽造成。

待确认：若用户希望更宽松但不增加二段跳，可扩大离墙容错窗口；若希望碰墙即获得一次可以稍后在空中使用的跳跃资格，则属于另一个玩法规则，需先确认，不自行增加。
